Mengapa Butuh IAT? (Analogi Buku Telepon)

Aplikasi Windows (EXE) sangat bergantung pada fungsi eksternal (sepertiMessageBox) dari fileDLL. Namun, karena alamat memori DLL selalu berubah-ubah di RAM (fitur keamanan ASLR), EXE tidak bisa "menghafal" alamat fungsi secara pasti (Hardcoded).

Analogi "Buku Telepon & Sang Manajer"

Bayangkan Anda menulis buku panduan masak (App.exe), lalu Anda menyuruh pembaca:"Pesan kue dari Toko Roti". Sayangnya, Anda tidak tahu alamat Toko Roti hari ini karena bangunannya sering berpindah.

  • INT (Import Name Table) - "Daftar Keinginan":Anda menuliskan string nama jasa yang Anda butuhkan (misal: "Pesan Kue"). Daftar nama ini tertanam abadi di dalam file EXE Anda.
  • IAT (Import Address Table) - "Buku Telepon Kosong":Anda menyediakan satu kotak kosong bersebelahan dengan daftar keinginan tadi.
  • Windows Loader (ntdll.dll) - "Sang Manajer OS":Saat Anda menjalankan program, Sang Manajer akan masuk. Ia membaca daftar keinginan (INT), terbang ke Toko Roti sungguhan, lalumenuliskan koordinat fisik toko tersebut menggunakan tinta merah ke dalam Buku Telepon Kosong (IAT)milik Anda.
  • Kini, instruksi mesin Anda (di.text) tinggal berkata:"Hai CPU, panggillah jasa yang alamatnya ada di Buku Telepon halaman 1!"

Mekanika EAT (Export Address Table) di dalam DLL

Jika IAT adalah "Daftar Permintaan", makaEAT (Export)adalah "Katalog Layanan" milik DLL. Agar Windows Loader bisa menjawab permintaan dari Aplikasi Anda, ia harus menelusuri katalog EAT milikUSER32.dllsecara dinamis menggunakan struktur rahasia berikut.

Translasi C++ & Peta RAM Vertikal (High to Low)

Bagaimana kode C++ yang simpel terhubung hingga keKernel Windows? Peta memori disusun secara vertikal dari alamat tinggi (Kernel/OS) ke alamat rendah (Aplikasi). Kita akan menelusuri eksekusi instruksiMessageBoxWdari awal hingga menembus batas OS melaluiSYSCALL.

Source Code C++ (Win32 GUI)
#include <windows.h>

int main() {
 // Memanggil fungsi GUI Windows
  MessageBoxW(NULL, L"Hello", L"GUI", MB_OK);
  return 0;
}
️ Compiled Assembly (x64 ABI)
; Persiapan 4 Argumen via Register (x64 Calling Convention)
mov r9d, 0          ; Arg 4: MB_OK
lea r8, [str_GUI]      ; Arg 3: L"GUI"
lea rdx, [str_Hello]     ; Arg 2: L"Hello"
xor ecx, ecx         ; Arg 1: NULL (0)

call qword ptr [__imp_MessageBoxW]; BACA IAT!
Hierarki Eksekusi Windows:Aplikasi Anda di *Ring 3* tidak punya hak akses untuk menggambar UI di layar perangkat keras. Ia harus memohon kepada Kernel (*Ring 0*).
